# 多 Worker 集成验证

本轮在原注册表、分阶段恢复和常驻消费测试之外，增加真实组件集成及故障注入。
测试直接使用 SQLite、任务执行器、心跳线程和消费者，不替换领取、提交或恢复协议。
需要控制并发顺序时使用 Event / Barrier；触发数据库异常时使用事务内 SQLite 触发器。

## 覆盖矩阵

| 方面 | 集成场景 | 检查的安全性质 |
| --- | --- | --- |
| 混合负载 | 4 个消费者、48 个任务，成功、失败、不同重试预算、延迟执行和重新打开数据库 | 次数符合预算、同任务 attempt 不重叠、持久化策略不受消费者默认配置影响 |
| 重复提交 | 多生产者在执行前、执行中及完成后并发重复提交 | 同业务键只调用一次，定义冲突被拒绝 |
| 调度 | 执行中追加高优先级任务、同级 FIFO、尚未到期的最高优先级任务 | 仅领取到期任务，高优先级先执行，同级保持顺序 |
| 优雅停止与重启 | 等待退避时停止旧 worker，再用相同 ID 启动新会话 | 重试保留，不丢任务，不重新扣预算 |
| 软超时 | 第一次业务调用仍活着，其他消费者继续处理健康任务 | 旧调用退出前不发起重试，心跳不被执行线程阻塞 |
| 读一致性 | 两个观察者在三个消费者执行和重试期间不断读取任务与事件 | 状态、结果、attempt 和重试次数对应同一已提交事件快照 |
| 结果提交故障 | 业务已调用，成功事件写入被数据库拒绝 | 结果和事件一起回滚；非幂等任务不重放，其他任务继续推进 |
| 心跳 I/O 故障 | 心跳接口异常，业务函数仍阻塞 | 停止后续领取，不把尚未结束的调用宣布为停止 |
| 停止依据提交故障 | STOPPED 审计写入失败 | 本地线程退出不等于持久化停止确认；未补充真实依据前禁止恢复 |
| 撤权事务故障 | FENCED 审计写入失败 | 撤权与审计一起回滚，权限保持原状态 |
| 线程启动与清理同时失败 | 心跳线程启动后，消费者启动失败，清理数据库写入也失败 | 本地生命周期正确，原始启动异常保留，数据库不会伪造停止依据 |
| 监测器启动失败 | 无法创建后台监测线程 | 失败后仍可安全关闭，不等待未启动线程 |
| 心跳与撤权竞态 | Barrier 同时触发心跳和撤权，独立重复 12 轮 | 一个事务先完成，恢复心跳取消旧失联判断，撤权后会话不能复活 |
| 完成与撤权竞态 | Barrier 同时触发结果提交和撤权，独立重复 12 轮 | 撤权前完成保留；撤权后完成被拒绝且无成功事件 |
| 多协调者与 ID 复用 | 4 个协调者并发恢复，同时注册新会话 | 每个中断任务只恢复一次、只扣一次预算，旧会话无法操作新会话 |
| 真实进程竞争 | 两个独立 Python 进程消费同一数据库 | 一个 attempt 只被领取一次，STARTED 事件绑定消费者会话 |
| 真实强制终止 | 业务副作用落库后强制终止子进程，健康消费者持续运行 | 恢复需分阶段确认，稳定业务键去重使副作用不重复 |
| 重试提交后的进程退出 | RETRYING 已提交，进程无清理钩子直接退出 | 数据库中的重试能继续领取，不依赖内存入队，不重复扣预算 |

## 独立执行

```powershell
$env:PYTHONPATH = 'src'
python -m pytest tests/test_multiworker_integration.py -q
python -m pytest tests/test_multiworker_processes.py -q
python -m pytest tests -q
```

`test_multiworker_integration.py` 包含负载、故障和竞态三个独立测试类。
`test_multiworker_processes.py` 使用实际子进程，进程和线程在失败时也执行清理。
SQLite 临时数据库建立在项目目录，避免 Windows 沙箱默认临时目录权限差异。

完整回归使用 pytest，同时收集 unittest.TestCase、pytest 测试类和顶层测试函数。
仅用 unittest discover 不会收集仓库的 pytest 风格不变量及系统场景用例。

## 验证结果（2026-10-11）

- 本轮新增 17 项集成测试；综合集成文件共 15 项，真实进程文件共 4 项（其中 2 项为此前已有）。
- 完整 `python -m pytest tests -q`：**273 passed**，包含全部 unittest 和 pytest 风格测试。
- 上述 19 项集成及进程用例连续重复执行 3 轮：每轮 **19 passed**。
- 心跳与撤权、完成与撤权两个竞态用例在每轮内各独立竞争 12 次。
- 原崩溃进程测试的 10 毫秒注册窗口会被机器调度延迟提前耗尽，现改用正常注册窗口，
  通过受控观测时钟触发失联，确保检查的是恢复协议而非机器调度速度。

当前覆盖的用例没有剩余测试失败。实际终止、事务回滚、业务调用次数、重试预算、
事件历史及运行时收尾均有明确断言；测试结论不扩展到未实现的跨主机协议。

## 本轮修复

- 消费者启动失败时，先正确终止本地生命周期，再尝试持久化清理；清理失败不会
  覆盖原始启动异常，也不会让 join 等待未启动的消费者线程。清理异常保留在
  `last_error`，数据库中的未确认会话继续禁止任务恢复。
- 监测器启动失败时，清除未启动线程并进入停止状态，后续 shutdown 可以安全调用。

上述边界均保留独立回归测试。验证范围是当前共享本机 SQLite 的实现，以及 supervisor
提供真实停止依据的接管协议；外部业务幂等性由业务键、唯一约束和事务保证。
